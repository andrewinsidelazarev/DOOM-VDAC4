# DOOM для VDAC4

![DOOM VDAC4: экран загрузки на FT812](assets/loader_screen_preview.png)

Порт [**doomgeneric**](https://github.com/ozkl/doomgeneric) для ZX Evolution / TS-Conf +
[**VDAC4**](https://github.com/andrewinsidelazarev/VDAC4), ESP32-S3 Zero N8R8.
Игра — загружаемое **DOOM.ELF** для штатного ядра ESP, не отдельная прошивка.
Игровая логика, BSP, отсечение, звук и программный рендер выполняются на ESP32; кадр идёт
через LINK QSPI в FT812 Slot1 Tang. С прошивкой BL616, где есть команды DOOM (в этот
репозиторий не входит), выборку текстур и отрисовку колонок/строк берёт на себя BL616. Ево
обслуживает SD через самостоятельный FAT32-драйвер и передаёт клавиатуру.

## Запуск

Положить **_DOOM.SPG** (с подчёркиванием — первым в списке файлов), **DOOM.ELF** и один IWAD —
**DOOM.WAD** (или DOOM2.WAD) — в **одну любую папку** на FAT32 SD Ево. Shareware DOOM1.WAD
переименовать в DOOM.WAD; прежнее имя загрузчик тоже находит (сохранения — `DUSAVEn.DSG` для
DOOM.WAD, `D1SAVEn.DSG` для DOOM1.WAD).
После штатной сборки программы находятся в `dist/DOOM/`; название этой папки можно изменить.
Запустить _DOOM.SPG обычным загрузчиком SPG. Wild Commander не требуется.

Для записи нужны **оба файла из выпуска 1.0: DOOM.ELF и _DOOM.SPG** (до 0.1.9 пакет назывался
DOOM.SPG — старый файл на карте больше не нужен).
До 0.1.8 сохранения игры и настройки на плате не записывались: первая передача данных
записи завершала DOOM ошибкой `File request queue full`. Причина — превышение предела
события ядра, 63 байта. Исправление работает через существующий ABI 1.3, в том числе
с установленной ESP 0.1.92; менять прошивку для него не требуется.

Запускатель сам монтирует FAT32 и ищет каталог, содержащий `DOOM.ELF` и
`DOOM2.WAD`, `DOOM.WAD` либо `DOOM1.WAD`. Имя и глубина каталога не зашиты.
При нескольких полных установках выбирается первая найденная при обходе в глубину.
В одной папке приоритет IWAD: DOOM2 → DOOM → DOOM1. Как в R-Type VDAC2+,
поиск читает записи каталога по секторам и сравнивает короткие имена файлов.
Стек хранит места возврата в родительские каталоги: количество соседних папок
его не расходует. Защитные пределы — 960 родителей, 65535 каталогов за обход,
4096 секторов в цепочке одного каталога. Ошибки чтения и превышение пределов
выводятся отдельными сообщениями.
Для однозначного выбора следует держать на карте одну полную установку порта.
Карта SD должна быть подключена к SD-ZC; драйвер поддерживает том FAT32,
раздел MBR и поддерживаемую цепочку EBR.

IWAD не входит в пакет программ. Используйте свой DOOM/Ultimate DOOM/DOOM II
или shareware DOOM1.WAD. Файлы игровых данных не становятся GPL вместе с движком.
Проверки этой сборки выполнены с DOOM shareware 1.9, первый эпизод.

Требуется штатная прошивка ESP с ABI 1.3 (`ft_open/ft_write/ft_read/ft_close`,
VDAC4 0.1.76 или новее), 8 МБ PSRAM и ядро FT812 Slot1 с LINK-хостом.
Рекомендуется актуальная совместимая сборка из исходного проекта VDAC4.
Порт сам включает M_SEL до запуска FT812. Первый переход может занять до 15 секунд.
Сборка игры не перепрошивает ESP32 или FPGA. Изменениями и установкой
прошивок занимается программист VDAC4. На текущей плате с BL616 v7 работает
программный рендер ESP; экспериментальный BL616 v8 для запуска не требуется.

Для этой Евы каталог установки — `\Games\VDAC4\DOOM VDAC4\`.
`tools/deploy.ps1 -LauncherOnly` заменяет только SPG по SMB в этой папке,
`-ElfOnly` — только DOOM.ELF;
параметр `-Target` задаёт другой уже существующий каталог. Имя каталога не
зашито в игру. Родительская `\Games\VDAC4\` содержит другие игры.
При переходе на новый протокол записи 0.1.8 заменить только один файл недостаточно.

При ошибке запуска выводится текст (`FILE NOT FOUND: DOOM.ELF`,
`FILE NOT FOUND: WAD BESIDE ELF`, `SD CARD INIT FAILED` и т. п.).
Под ним — этап и код для диагностики. `tools/read_boot.py` читает эти же
байты по сети из FT_SEEN Tang; метки не запускают Slot1 и не требуют ELF.

## Управление

| Клавиши PS/2 | Действие |
|---|---|
| Стрелки / W, S, A, D | Ход и поворот; навигация по меню |
| Q / E или запятая / точка | Шаг влево / вправо |
| Ctrl / F; Space; Shift; Alt | Огонь; использовать; бег; стрейф |
| Esc; Backspace; Enter | Открыть/закрыть меню; назад; выбрать |
| F2 / F3; F6 / F9 | Сохранить / загрузить; быстро сохранить / загрузить |
| F4 | Sound Volume: громкость SFX и Music |
| Tab / M; P; 1…7 | Карта; пауза; оружие |
| Мышь Kempston | Поворот и ход; левая — огонь, правая — стрейф, средняя — вперёд |

Клавиатура читается только из очереди PS/2 AVR Evo, матрица ZX не используется.
Буквы и Backspace работают в названии сохранения. Quit Game → Y сохраняет изменения
и завершает ELF; Reset возвращает к загрузчику. Настройки из меню сохраняются при уходе
с Options или Sound Volume. Горячие клавиши `-`/`=`, F5, F8, F11 сохраняются автоматически
после примерно секунды без новых изменений. Перед Reset дождитесь окончания этой паузы
и записи; после изменения ползунков в меню сначала выйдите с экрана настроек.

## Сохранения

Все сохранения, временный файл и настройки лежат **рядом с ELF и WAD**,
в найденной папке игры. Каталоги `/DOOM`, `/WC`, `.savegame` не создаются.
Внешних звуковых ELF и банков нет.

- `D1SAVE0.DSG`…`D1SAVE5.DSG` — shareware DOOM1.WAD;
- `DUSAVE0.DSG`…`DUSAVE5.DSG` — DOOM.WAD;
- `D2SAVE0.DSG`…`D2SAVE5.DSG` — DOOM2.WAD;
- `TEMP.DSG` — промежуточный файл; `DEFAULT.CFG`, `DOOM.CFG` — настройки;
  `TEMP.CFG` — промежуточный файл настроек.

Настройки читаются при запуске. Движок отслеживает все привязанные значения обеих коллекций,
включая размер экрана `screenblocks`, детализацию `detaillevel`, сообщения `show_messages`
и гамму `usegamma` (0…4). В игре серия изменений вызывает одну запись после секунды покоя.
В Options и Sound Volume запись откладывается до ухода с экрана и тогда выполняется сразу;
Quit Game → Y тоже сохраняет оставшиеся изменения. Без изменений, в том числе при возврате
к сохранённым значениям до записи, обращения на запись нет. После отказа SD следующая попытка
будет только при новом изменении. Запись — как у сохранений: сначала целиком в `TEMP.CFG`, затем FILEX MOVE_RENAME с REPLACE
заменяет `DEFAULT.CFG` (меню Options, клавиши, звук, `use_mouse`) или `DOOM.CFG`
(`vdac4_bilinear`, `vdac4_mouse_scale`, `novert`, `mouse_acceleration` и прочее
Chocolate Doom). Отказ записи на SD оставляет прежние файлы, выход штатный. Файлы —
текст «имя значение» в строке, их можно править и на ПК; незнакомые строки пропускаются.

Громкость находится в **DEFAULT.CFG**, ключи `sfx_volume` и `music_volume`, диапазон **0…15**.
В `DOOM.CFG` этих ключей нет: это другая коллекция настроек. В меню оба ползунка находятся
в **Options → Sound Volume**, прямой вход — **F4**. При старте `S_Init` применяет прочитанные
значения к микшеру (шкала 0…120, значение из файла ×8); начальное внутреннее значение Music 90
при этом заменяется. Отсутствующий DEFAULT.CFG означает исходные значения 8/8; файл появится
при сохранении настроек. Изменение ползунков применяется сразу, запись выполняется при уходе
с экрана. Reset во время записи не даёт гарантии сохранности FAT.


Сохранение сериализуется оригинальным кодом DOOM, записывается кусками через
FAT32 FILEX WRITE_AT, синхронизируется и заменяет выбранный слот через FILEX
MOVE_RENAME с REPLACE. Старый слот не удаляется перед записью TEMP.DSG.
Ошибка записи или замены не выдаётся за успешное сохранение: игра останавливается
с ошибкой, подробности доступны в журнале ESP. После перезапуска можно загрузить
предыдущий слот. Это не гарантия целостности FAT при обрыве питания непосредственно
во время обновления метаданных карты.

Обмен записи в 0.1.8: E5 — только заголовок **35 байт**; Z80 запрашивает данные
командой `76 [seq16]`, ELF отвечает `F6 [seq16,ok8,count16,data]`, до **960 байт** данных
(965 байт ответа). После проверки длины и номера запроса Z80 вызывает WRITE_AT и
возвращает результат командой 74. Повторная выдача данных, чужой seq и успешный 74 до
выдачи данных отвергаются. Других событий, кроме E4 (8 байт) и E5 (35 байт), игра не посылает.

Новый ELF со старым SPG получает отказ записи `0x10`: старый ServeFile не находит
данных внутри E5. Старый ELF с новым SPG также не может писать: длинное событие
отвергает ядро, а короткую запись старого формата — новый ServeFile со статусом `0x10`.
Прежние целевые CFG/DSG остаются на месте; может остаться созданный или усечённый TEMP.
Ошибка сохранения игры останавливает игру, ошибка записи настроек выводится в журнал.
Обновлять ELF и SPG следует вместе, из одной сборки текущего дерева 0.1.8.

## Видео и звук

Рендер 320×200, 256 цветов; двойной буфер индексов и палитры RGB565 в RAM_G.
Лист FT812 масштабирует изображение до 960×720 на выходе 1024×768 с коррекцией
пропорций пикселя. Индексы и палитра меняются согласованно через DLSWAP.
ESP выбирает оригинальные COLORMAP по освещению и расстоянию, BL616 применяет
их к текселям. Поддержаны переводы цветов, прозрачность демонов (fuzz), низкая
детализация и уменьшенное окно. Вспышки палитры и UI остаются на ESP.
В программном режиме полный кадр и палитра — 64 512 байт через QSPI.

PCM-сэмплы эффектов из WAD смешиваются на ESP; музыка MUS воспроизводится
компактным FM-синтезатором внутри ELF. Его тембры **не совпадают с OPL оригинала**.
MIDI и внешние музыкальные банки не поддерживаются. Поток 22050 Гц, стерео;
ядро VDAC4 выводит звук через I2S на PCM5102. Музыка не требует `/wc/`.

В журнале ESP раз в 5 секунд: FPS, миллисекунды рендера вида игрока,
передачи QSPI и ожидания DLSWAP. Замеры позволяют отделить работу ESP от
ограничений передачи и растеризатора. О реализации BL616-ускорения —
[docs/BL616.md](docs/BL616.md).

## Сборка и проверки

На текущем компьютере:

```powershell
.\tools\build.ps1
E:\zx\esp\fat32-venv\Scripts\python.exe tests\test_launcher.py
python tests\build_host.py
python tests\run_host.py путь\к\DOOM1.WAD
```

`tools/build.ps1` использует ESP-IDF из `E:\zx\esp\idf-env.ps1`, sjasmplus и
spgbld из `E:\zx\z80\zuma`. Путь проекта VDAC4 можно задать параметром `-Vdac4`.
`-SkipEsp` повторно упаковывает уже собранный ELF. ELF собирается специальной
целью `elf` существующего загрузчика; обычный firmware.bin не является игрой.
SPG содержит код Z80 и обе страницы FAT32, ELF и WAD остаются отдельными файлами.

Для проверки настоящего движка на ПК используются clang-cl, VS Build Tools
с библиотеками x86 и Python с Pillow. Для Z80-тестов нужен пакет `z80` и модели
SPI из проекта VDAC4; `VDAC4_ROOT` меняет путь к нему.

Подробности текущего прогона — [VALIDATION.md](VALIDATION.md). Проверены:
компиляция ELF и импорты/секции/указатели загрузчика, исполнение Z80-кода,
поиск произвольного каталога, файлы с фрагментированными цепочками, сохранение
после перезапуска, отказ записи, реальная игра E1M1 и сохранение через меню.
**На физической VDAC4 подтверждена работа игры.** После восстановления LINK
программистом (ESP 0.1.79, Tang 1.23, BL616 v7) программный рендер выдавал
5,0–6,1 FPS после прогрева; передача кадра занимала 146–147 мс.
Новый ELF передаёт только изменившиеся участки обоих видеобуферов и палитру
при изменении. На ПК проверено побайтное совпадение кадров; аппаратный FPS
этой оптимизации пока не измерен. Свежие результаты — в начале VALIDATION.md.

0.1.1 (2026-10-20, собрано, на плате ещё не проверено). 146 мс на кадр уходили не на
провод: ESP слал каждое 32-битное слово окна FT_DATA отдельной транзакцией LINK с полной
настройкой контроллера (~9 мкс на слово, сам провод на 26,67 МГц — ~0,9 мкс). ESP
vdac4-0.1.80 пишет слова подряд без перенастройки (`link_spi3::writeRepeat`), а ядро Tang
1.25 отмечает слово, потерянное в занятом окне (FT_STAT 14), — тогда блок повторяется
медленно. Сам DOOM 0.1.1 выгружает кадр в отдельной задаче на ядре 0, пока игра на
ядре 1 рисует следующий, и пишет блоками по 4 КБ. В журнале добавлено «upload wait» —
сколько игра ждала выгрузку. Скорость окна меряет команда сетевой консоли ESP
`tang ftspeed 64`.

0.1.2 (2026-10-20, собрано, на плате ещё не проверено). Ровный темп: лист меняется раз в
2 кадра FT812 по `REG_FRAMES` — 29,54 кадра/с, каждый кадр виден одинаково долго (раньше
смена шла на первом же кадре FT812, и кадры держались то 1, то 2 кадра). Игра считает те же
35 тиков в секунду. На выгрузку остаётся 33,8 мс. В журнале добавлены «pace wait» (ожидание
темпа) и «late» (сколько кадров за 5 с продержались дольше двух кадров FT812). Растяжение —
BILINEAR (`vdac4_bilinear` в DOOM.CFG, по умолчанию 1; 0 — NEAREST). Растеризатору ядра Tang
1.26 это стоит ~22–24 мс на кадр (стенд), в темп 29,5 кадра/с укладывается. С ядром 1.25 —
~40 мс, темп упадёт до ~20 кадров/с; до 1.25 BILINEAR рисуется как NEAREST.

0.1.3 (2026-10-20, собрано, на плате ещё не проверено). Экран загрузки: картинка «DOOM ZX
Evolution» (`assets/loader.png`, её нарисовал Codex) и полоса загрузки на FT812, пока DOOM
читает WAD через Evo. Картинка лежит в ELF как JPEG 1024×768 (206 КБ, `main/loader_image.c` —
`tools/make_loader_image.py`). Сопроцессор BL616 распаковывает её командой CMD_LOADIMAGE (с
OPT_NODL) в RAM_G по 0x080000, на экран она идёт один к одному. Если BL616 не отвечает,
картинки нет и полоса идёт на чёрном.

Полоса показывает байты WAD, прочитанные через Evo, против оценки по каталогу WAD:
- в оценку входят спрайты, патчи стен, PLAYPAL, COLORMAP, PNAMES, TEXTURE1/2, графика ST*,
  TITLEPIC, музыка заставки и дважды сам каталог, плюс 5 %;
- над полосой — строка этапа из printf DOOM («R_Init: Init DOOM refresh daemon»), справа —
  проценты, под полосой — WAD и прочитанные мегабайты;
- ошибка загрузки показывается красным.

Рисует экран своя задача на ядре 0, примерно 30 кадров/с: лист `main/loader_dl.c`, задача
`main/loader.c`. Перед первым кадром игры полоса доходит до 100 %, и задача выходит. Шрифты
ПЗУ FT812 26, 27 и 29 — латиница, поэтому подписи на английском, как сама загрузка DOOM.

Предпросмотр на ПК: `python tests/loader_preview.py OUT` — лист из `loader_dl.c`, кадры рисует
модель растеризатора Tang.

0.1.4 (2026-10-20, собрано, на плате ещё не проверено). Мышь Kempston. Загрузчик в каждом
пакете клавиш 0x72 читает три порта мыши Evo и передаёт их как есть: пакет вырос с 9 до 12
байт — матрица 8 байт, Kempston-джойстик, затем кнопки `#FADF` (бит 0 левая, 1 правая,
2 средняя; нажатая — 0), X `#FBDF` (растёт вправо), Y `#FFDF` (растёт вверх). X и Y —
счётчики по модулю 256; разность с прошлым пакетом считает ESP, поэтому потерянный пакет не
теряет движение. Без мыши все три порта дают `#FF` — тогда движения нет, отсчёт начинается
заново. Совместимость: ELF 0.1.4 принимает и старый 9-байтный пакет (мыши нет); старый ELF
отвечает на 12 байт отказом, и загрузчик 0.1.4 переходит на 9 байт — клавиатура работает,
мыши нет. Мышь нужна от обоих файлов 0.1.4.

В игре — как у Chocolate Doom: раз в тик событие `ev_mouse` (кнопки, поворот, ход), ускорение
`mouse_acceleration` 2,0 выше `mouse_threshold` 10. Мышь включена (`use_mouse` 1); `novert` 1
убирает ход мышью вперёд-назад. AVR Evo кладёт в счётчики отсчёты PS/2 без масштаба, по
умолчанию 1 отсчёт на мм, поэтому DOOM умножает их на `vdac4_mouse_scale` = 16: полный поворот —
26–30 см хода при чувствительности 5. Быстрее или медленнее — ползунок Mouse sensitivity в
меню Options (множитель 0,5…1,4) или разрешение мыши самой Evo: удерживая обе кнопки мыши,
«+» / «−» на цифровом блоке (1, 2, 4, 8 отсчётов на мм), «*» — 1 отсчёт на мм. Исходники AVR,
по которым это выяснено, — `docs/references/evo-mouse-2026-10-20/`.

Настройки DEFAULT.CFG и DOOM.CFG в 0.1.4 и раньше не читались и не записывались: загрузка и
запись в `m_config.c` стояли под `#if ORIGCODE`, а `config.h` его отменяет. Этот код включён
в 0.1.5; аппаратную запись всё ещё блокировал размер E5, исправленный только в 0.1.8.

Клавиатура — только очередь скан-кодов PS/2 (набор 2) контроллера AVR Evo, как в R-Type, WC и

(`SendKeys`) открывает регистры Gluk (`#EFF7` = #80), один раз включает очередь (`#0C` = 1 —
сброс, `#F0` = 2 — приём) и на каждом опросе читает `#F0` до нуля, не больше 24 байт; байты
уходят в DOOM.ELF как есть (пакет `75`: джойстик Kempston, мышь, байты PS/2). DOOM.ELF (`video.c`)
разбирает E0/F0 и переводит коды в клавиши DOOM, как на ПК: стрелки, Ctrl — огонь, пробел —
«использовать», Alt — стрейф, Shift — бег, «,» и «.» — шаг вбок, Esc — меню, F1…F12, Tab —
карта, цифры — оружие, буквы — имена сохранений и чит-коды; остались привычные W/A/S/D, Q/E, F,
M и P (Pause очередь AVR не пишет). Переполнение очереди (#FF) и молчание клавиатуры дольше
500 мс отпускают все клавиши. Аварийного выхода Caps Shift + Symbol Shift + Space больше нет — он
был на матрице; выход — Quit Game.

ключ — имя программы («DOOM») и серийный номер тома FAT32, значение — кластер каталога. На карте
ничего не пишется: `DOOMPATH.CFG` из 0.1.6 в корне карты больше не нужен, его можно удалить.
