Программисту прошивки VDAC4: передача кадра ESP -> Tang
19.10.2026. Исходники прошивок автором DOOM не изменяются.

Плата после восстановления LINK
ESP vdac4-0.1.79, Tang Slot1 1.23, BL616 v7 (CP_INFO C00700E9).
DOOM работает с программным рендером на ESP; пользователь подтвердил запуск.
Кадр с реальной платы: build/hardware/link-restored/preview.png.
Логи: build/link-restored-first-frame.log, build/link-restored-warm.log.

Измерение перед планируемым удвоением частоты SDRAM
В прогретой сцене: render около 8 мс/view, QSPI около 146 мс/frame,
swap wait 0-2 мс. Последний отчёт первого замера — 5.5 FPS.
При первом входе в уровень наблюдались 1.2-3.5 FPS с подгрузкой ресурсов;
экран заголовка выдавал 6.5 FPS. Эти значения относятся к разным моментам
игры и не являются сравнением одинаковых кадров.

За кадр в программном режиме ELF отправляет 64000 байт индексов и 512 байт
палитры, затем 88 байт display list и DLSWAP. Счётчик QSPI охватывает этот
путь целиком, включая накладные расходы вызовов и проверки. Около 0.44 МБ/с
полезного потока; это не измерение максимальной скорости самой шины QSPI.

Наблюдение при чтении текущего исходника ESP
Firmware/src/ft_host.cpp: writeWords(), строки 48-64:
  for (...) tang::write(tang::kRegFtData, &words[i], 1)
Даже ft_write(address, data, 256) разбивается на отдельную LINK-транзакцию
для каждого 32-битного слова. writeBlock() дополнительно читает последнее
слово и при несовпадении повторяет блок с ожиданием после каждого слова.
DOOM уже передаёт порции до 256 слов через штатный ELF ABI 1.3.

Нужно проверить
1. После изменения SDRAM измерить те же render/QSPI/swap в прогретой сцене.
2. Разделить время передачи на накладные расходы LINK, ожидание памяти,
   чтение контроля и повторную передачу paced. Удвоение частоты SDRAM само
   по себе не устраняет отдельную транзакцию на каждое слово.
3. Если лимит остаётся в LINK, предусмотреть пакетную запись последовательных
   слов RAM_G через FT_DATA с корректным backpressure. Сохранить существующий
   ABI ft_write(address, words, count); реализацию выбирает программист прошивки.
4. Записи регистров с побочным действием не должны повторяться как блок данных.

Критерии проверки
Полная побайтная проверка блоков RAM_G на случайных данных, в том числе с
одинаковым последним словом разных блоков; границы и произвольные длины;
одновременная работа растеризатора и других пользователей LINK; отсутствие
потерь слов, зависаний, повторного DLSWAP. Затем измерение реального кадра
DOOM и проверка BOING/DEMO3D. Цель — уменьшение измеренных 146 мс передачи,
а не только увеличение частоты в отчёте.

Это задание на оценку и реализацию программистом. Ранее собранный автором
DOOM экспериментальный образ BL616 v8 устанавливать для этой проверки не нужно.
