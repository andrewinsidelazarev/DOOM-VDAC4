# Рендер DOOM на BL616

Прошивка версии 8 добавляет команды `0xFFFFFFB0…B6` в сопроцессор FT812.
Исходники: `firmware/bl616/copro/ft_doom.{c,h}`, передача со стороны ELF:
`main/gpu.c`. Игровая логика, звук, BSP, отсечение и выбор номера COLORMAP
остаются на ESP. Пиксельные циклы стен, пола, потолка и спрайтов выполняет BL616.

Это перенос целочисленных колонок и строк исходного DOOM. Прежние команды
треугольных сеток `A0…AC` сохраняются; DOOM не превращает карту в сетку.

| Команда | Назначение |
|---|---|
| INFO | Версия `0x444F0100` и возможности; состояние рендера не меняет |
| BEGIN | Начало кадра 320×200, область вида и фон вне неё |
| MAPS | 34 COLORMAP и три таблицы перевода цветов |
| COLUMN | Текстурная или fuzz-колонка шириной 1/2 пикселя |
| SPAN | Строка пола/потолка с текстурой 64×64 |
| COPY | Наложение пикселей UI, включая невыровненные участки |
| END | Запись готового индексного кадра в RAM_G |

Полные параметры и упаковка полей описаны в `ft_doom.h`. Команды идут через
штатное кольцо RAM_CMD, с ожиданием REG_CMD_READ и проверкой ошибок. Ссылки
на текстуры содержат поколение: повторное использование адреса RAM_G не
возвращает старые тексели из кэша. До перезаписи используемого слота ESP
дожидается выполнения предыдущих команд.

BL616 хранит кадр 64 000 байт, таблицы цветов, 128 колонок по 256 байт и
восемь текстур по 4096 байт. Область `ft_doom_t` — 140 128 байт; она находится
в union с памятью прежнего 3D, поэтому обе сцены одновременно не сохраняются.
Переключение режима переинициализирует соответствующий рендер.

В ELF сохраняются аппаратно независимые меню/HUD и палитровые эффекты.
При переходах wipe приложение может прочитать готовый индексный кадр обратно.
Старый BL616 без INFO вызывает сброс кольца и возврат к рендеру на ESP.

`tools/build_bl616.ps1` собирает `dist/BL616/DOOMCP.BIN`. Установка возможна
штатным `tang_tool.py bl616`. 19.10.2026 образ установлен на плату: проверен
SHA-256, получен ответ `CP_INFO C0080001` — версия 8 работает. Следующий
запуск подтвердил `BL616 Doom textured renderer ABI 1 enabled` и дал игровой
кадр (`build/hardware/bl616/preview.png`). Первая аппаратная версия даёт
0,7–2,8 FPS в игровом виде, то есть медленнее программного рендера ESP.

Исправление в новом ELF сохраняет несэмплированную часть колонки кэша:
изменение отсечения камерой больше не создаёт новую нулевую текстуру.
Читается только допустимый диапазон поста спрайта; при повторном использовании
адреса zone-памяти сравниваются актуальные байты. Кэш четырёхканальный,
перед заменой занятого слота выполняется синхронизация. Для плоскостей один
проверенный слот переиспользуется в пределах текущей плоскости. Очередь
команд ожидает свободное место в кольце, а не полное завершение предыдущего
пакета. Новая версия прошла сравнение пикселей, в том числе с задержанным
потребителем FIFO; её скорость на плате ещё не измерена.

`tests/test_bl616.py` проверяет пиксели и протокол на независимом эталоне.
Host-сборка с `VD_GPU_VERIFY=1` одновременно исполняет исходный DOOM-рендер
и BL616 и сравнивает кадры побайтно. `tests/render_comparison.py` создаёт
из этих реальных буферов сравнение; получено ноль отличающихся пикселей.
